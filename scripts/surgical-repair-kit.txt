Guarded content repair
======================

The old direct live-patch recipes are retired. Use the local guarded scripts.
They default to a preview, require an explicitly acknowledged project/dataset
for --apply, preserve originals in .local-backups/sanity, and reject stale revisions.

Preview the bounded repair plan (no network writes):
  node scripts/repair-live-content.mjs

Application syntax (replace both placeholders with the configured target):
  node scripts/repair-live-content.mjs --apply --target=<dataset> --project=<project>

Preview schema/content migration plans:
  node scripts/migrate-service-schema.mjs
  node scripts/migrate-service-page-content.mjs
  node scripts/migrate-to-service-pages.mjs

See docs/operations/repository-release-security.md for credentials, private
backup permissions, revision conflicts, and release gates. Keep backups local.
Do not restore content automatically or run production writes during verification.
